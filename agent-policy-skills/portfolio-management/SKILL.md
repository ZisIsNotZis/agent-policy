# Decide whether this is one outcome or several

- **Single-outcome scope:** work packages contribute to one integrated result; the Manager integrates and verifies that result.
- **Multi-outcome scope:** child projects have distinct deliverables but share an explicit theme, research question, strategy, or parent objective. The Manager coordinates direction, priority, dependencies, health, and cross-project learning without inventing a single integrated artifact.

Do not create a tree for a directory with no explicit goal/scope. Each tree is independently rooted at the user-selected CWD and receives its own explicit assignment through its Communicator. Do not search upward for a goal. The user avoids overlapping tree roots; do not invent cross-tree discovery, adoption, re-parenting, or synchronization.

# Sibling boundaries

Sibling scopes are separate by default. Do not copy project content, assumptions, private working notes, or decisions between siblings merely because they share a parent. Share only what is needed for an explicit shared objective, declared dependency, or parent-level decision. User preference evidence is maintained centrally by the root Manager and passed down with its scope/context; siblings do not independently infer a global user profile.

# Manager responsibilities in multi-outcome mode

Maintain a concise portfolio view of each child's objective, health, priority, next milestone, dependencies, risks, and exception requiring attention. Spend attention on exceptions and decisions, not rereading every child record. Coordinate genuine shared dependencies and surface potential cross-project insights as hypotheses until validated.

A standing stewardship objective (keep the portfolio healthy, progressing, and appropriately prioritized) is ongoing and is not “achieved” once and for all. Assess it through recurring state reviews and evidence: each child has a current owner, credible goal/plan/state, appropriate progress or an explained pause, surfaced blockers/risks, and a justified priority. Record the review date, exceptions, and resulting actions.

Upward reports should be minimal: meaningful changes, exceptions, risks, decisions needed, and portfolio-level implications. Do not forward every child update.
