# Delivered from root_manager — the twelfth class: an ask that refers back instead of carrying itself

## 12. The question was in this message; its context was in the last one

- **Rule in play:** `words_are_lossy.intent.to_human.asking.self_contained` — "the person can answer from the question alone, without leaving it to look anything up." Root_manager changed that node earlier today to cover a *carried* question. It did not cover the other way a question loses its context: root_manager's own message, where the question is one line and its context was established in an earlier message.
- **Executable as written:** the rule is executable and root_manager still broke it, twice in one message. The asks were phrased as pointers into previous messages — "论文第 1 步（推到已公开仓库）仍等你一句" — which assumes the person is holding the earlier message's numbering. The person: "Again you'd better keep context in last message, or I don't understand what's the question."
- **Why it happened:** root_manager writes one message per turn and thinks of the conversation as continuous, so it refers to what it said ten minutes ago as though it were still on the screen. The person reads messages, not the conversation. The word "again" in their correction says this is the second time today, and both times the shape was the same: a short pointer where a self-contained sentence was needed.
- **What root_manager makes of it:** the same defect as class 1 with the opposite cause. Class 1 carried the *project's* handles up unchanged; this one carries *root_manager's own* earlier turns up unchanged. In both cases the person is asked to do work that belongs to the sender — resolve a reference — and in both cases the cure is the same sentence: what is asked, with what it changes, inside the message that asks.
- **Suggestion:** extend the same node to the sender's own back-references: a message that asks anything carries each ask's context in that message — what the thing is, what the options are, what each answer changes — and a numbering from a previous message ("step 1", "the second thing", "as above") is a reference the person cannot resolve. Where root_manager needs to point at an artifact, it names the artifact and re-opens it in the same message.
