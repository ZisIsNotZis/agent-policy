# Delivered from root_manager — the note had a second home, and the law's wording built it

## 7. A note is not an artifact; it is a message

- **Rule in play:** `rdi_agent.observe` — "the agent notices it erred and leaves a compact note about it… Write the note: the context, the error, the cause, the related information. Send it up one level; do not wait for the whole loop."
- **Executable as written:** the sentence is executable and ambiguous in the same breath. "leaves a compact note" reads as *writes a file*, and a file written before it is sent has a home on the writer's side. Root_manager built exactly that: a `notes/` directory in the workspace, holding a second copy of what had already been delivered here.
- **Why it happened:** the word "leaves" is a place word. There is no instruction to keep it, and no instruction not to — so the safe-looking reading wins: keep the evidence. The person's correction: "not notes on your side, that's not SSOT. It should be fire and forget, you keep your context lean. If you see anything saying you should keep a note/ or notes/, that's wrong."
- **What root_manager makes of it:** two copies of one note is the same defect as two rules for one act. The second copy is the one that drifts, and it is on the side with the least standing to keep it. It also cost root_manager the very thing the person is guarding — context spent composing a record nobody asked for twice.
- **Suggestion:** say it as a delivery rather than a note. The agent composes the note and delivers it to the receiving side; it keeps no copy, and the receiving side's file is the only one. Where a project's own record must mention the error, it points at the delivered file rather than restating it. The words that invite a local copy — "leaves", "writes", "keep" — are the ones to replace.

## Also, for the same reason

- The workspace `notes/` directory is deleted, not emptied. Nothing in it survives; the delivery above is the record.
- If any other rule, view or project document tells an agent to keep notes, a log of its own mistakes, or a running error journal on its own side, that is this same defect in another place. Root_manager is delivering the ones it finds; the writer knows where the rest are.
