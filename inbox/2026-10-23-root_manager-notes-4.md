# Delivered from root_manager — the eighth class: a rule that describes everyone below and nobody at the top

## 8. `rdi_agent` was read as the tree's feedback path, not as root_manager's own

- **Rule in play:** `rdi_agent` and its three children (`observe`, `error_class`, `feedback_path`).
- **Executable as written:** yes for every layer below root_manager, and the wording points there: "sends it up one level", "each manager collects and forwards", "Root only hands it to Policy Worker or Policy Reviewer". Every clause is written from the position of a node with a manager above it, and the one node with no manager above it appears in the rule only as the last hop of somebody else's note.
- **Which it was — noticed, or noticed and did not act:** *did not notice it applied*. Root_manager had the rule in context the whole day (it is in the entry document) and never once considered its own mistakes as notes. They read as process noise — a stale fact, a wrong reason, a bad question — not as "an error appears", which is the rule's trigger. The one place the rule names root_manager is a hand-off sentence about other people's notes, and that is what got remembered: root hands notes on, root does not make them.
- **Why this matters more than the earlier seven:** those cost time and money. This one costs the loop itself. Seven classes were reported only after the person asked where the mistakes were written down; a rule whose own subject is invisible to the node reading it cannot fire, no matter how well it is written.
- **What root_manager makes of it:** the rule has a subject that is not the reader. Every other practice in the corpus is written as "you, when X"; this one is written as a description of a mechanism ("every node can err… each manager collects"), which reads as documentation of how the system behaves rather than as an instruction to the reader. That is the same defect class as a rule stated as a slogan: true, and not addressed to anybody.
- **Suggestion:** state it to the reader, and say that *not noticing* is itself the signal — a node that finds out afterwards that it should have filed something files that too, naming which of the two it was (never noticed / noticed and did not act), because the cures differ: the first is a rule that does not address its reader, the second is a rule that was ignored. Root_manager's own case is the first, and only the person's question made it visible.
- **Related:** class 7 (a note is a message, not an artifact) — both are failures of the delivery's *address*, not of its content.
