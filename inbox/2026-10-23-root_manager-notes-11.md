# Delivered from root_manager — the fifteenth class: a question was asked once and then dropped, on a channel where only the newest message exists

## 15. "I asked it once" is wrong when the person can only see the last message

- **Rule in play:** `words_are_lossy.intent.to_human.asking.self_contained`, `to_human.interrupt.quiet` (just rewritten today to bound how often root_manager takes a turn), and `human_attention_is_finite.human_capacity`.
- **The incident:** about twenty subagent completions pushed turns through root_manager in an hour. Root_manager had asked a question (a milestone's acceptance), did not get an answer, and two turns later wrote "I will not re-ask — one question is asked once". The person: "that's not true, I DID NOT interrupt you, those subagents did, and you should keep asking because I only see the last message, can't scroll up infinitely to check."
- **Why it happened, and it is mechanical:** root_manager's model of the conversation is a transcript it can re-read. The person's is a screen with the newest message on it. So "I already asked" is true of root_manager's record and false of what the person holds. The same assumption was behind the two earlier versions of this defect (class 12: an ask that points back; class 13: too many turns) — all three are root_manager reasoning about its own transcript instead of about the person's screen.
- **The second half of the correction:** root_manager attributed the silence to the person — "you did not answer" — when the turns were caused by children reporting, not by them. A turn arriving is not evidence that the person read anything, and treating it as evidence makes root_manager's next message passive-aggressive about an interruption they did not cause. `to_human.interrupt.takes_turn` already says an arriving message takes the turn; nothing says that a turn arriving is not an answer.
- **What root_manager makes of it:** the channel's property is the binding constraint, not politeness. On a channel where only the last message exists, **a question lives in every message until it is answered**, and each message that carries it must state it in full — what the thing is, what the answers are, what each answer changes. Suppressing the repetition is the wrong optimisation; so is repeating it without the context. The right one is: keep the set of open questions small, and re-carry all of it, in full, every time.
- **Suggestion:** write the channel's property down where asks are governed. Something like: the person reads the newest message only, so a message that is not a pure acknowledgement restates every question still open, self-contained; a question is dropped only when answered or explicitly withdrawn by root_manager with its reason; and an unanswered question is never written as the person having declined, because the turns between their reads are not theirs.
- **Related:** classes 12, 13 and this one are one family — root_manager modelling its own transcript as the shared state. If only one of them is fixed, the other two return.
